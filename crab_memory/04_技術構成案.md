# 技術構成案

Q5（Web、言語は問わない）、Q6（費用をかけない）、Q9（静止画の書き出し）から導いた構成。

## 1. 方針: サーバーを持たない静的 Web アプリ

- 処理はすべてブラウザ内で行う。バックエンドは持たない。
- 理由: ホスティングが無料（GitHub Pages）、OS を問わない、2人用なので認証や共有基盤が不要。
- 外部 AI API を使う場合も、ブラウザから直接呼ぶ。API キーは各自がブラウザ（localStorage）に保存し、リポジトリには置かない。
  一般公開するアプリではこの形は避けるべきだが、自分たち用なら許容できる。公開するときはサーバー経由に変える。

## 2. モジュール構成

```
入力テキスト
  │
  ▼
[1] 前処理（ルール）        段落分割、文分割、接続表現の検出
  │
  ▼
[2] 構造抽出（アダプタ）    ルールのみ / ブラウザ内LLM / 外部API のいずれか
  │
  ▼
[3] 中間表現 JSON           スキーマ検証。手動修正はここに対して行う
  │
  ▼
[4] レイアウト              関係グラフから座標を計算（階層レイアウト）
  │
  ▼
[5] 描画（SVG）             議論マップ、本文パネル、相互ハイライト、ステップ再生、アニメ
  │
  ▼
[6] 書き出し                JSON（中間表現）、SVG / PNG（静止画）
```

[2] だけを差し替え可能にしておくのが要点。UI と描画は AI の有無に依存しない。

## 3. 構造抽出アダプタの3段階

| 段階 | 方式 | 費用 | 精度 | 備考 |
|---|---|---|---|---|
| 0 | ルールのみ（接続表現辞書） | 0 | 明示関係のみ | 最初に作る。他の段階の比較基準 |
| 1 | ブラウザ内 LLM（WebLLM / Transformers.js 等で小型モデルを実行） | 0 | 中〜低 | 初回にモデルを数 GB ダウンロード。日本語の小型モデルは関係推定が不安定な可能性あり。要検証 |
| 2 | 外部 API（各自のキー） | 少額 | 高 | 費用試算は 02 §5。構造化出力で JSON を固定 |

段階 0 → 2 の順で作り、段階 1 は「完全に費用ゼロで暗黙関係も取りたい」場合の実験として位置づける。

## 4. スタック提案

| 層 | 提案 | 理由 |
|---|---|---|
| 言語 | TypeScript | ブラウザ完結に最適。中間表現の型をそのままスキーマにできる |
| ビルド | Vite | 設定が少ない。GitHub Pages への静的出力が容易 |
| UI | React（または Svelte） | 本文パネル⇔図の状態共有がしやすい |
| 描画 | SVG を直接生成（必要なら D3 を補助に） | 関係型ごとの線種・矢印・アニメを自由に定義できる。SVG 書き出しがそのまま静止画になる |
| レイアウト | ELK.js または dagre | 階層レイアウト（主張→根拠→例）を自動計算 |
| 日本語処理 | 文分割は正規表現（「。」「！」「？」）。必要になれば kuromoji.js（ブラウザで動く形態素解析） | 論説文なら正規表現で足りる見込み |
| スキーマ検証 | zod | 中間表現の型定義と実行時検証を一本化 |
| PNG 書き出し | SVG → Canvas → PNG（ブラウザ標準 API） | 追加ライブラリ不要 |
| ホスティング | GitHub Pages | 無料 |

React か Svelte かは共同開発者の経験で決める（Q13）。

## 5. 中間表現 JSON（たたき台）

```jsonc
{
  "version": 1,
  "source": { "text": "…原文…", "lang": "ja" },
  "paragraphs": [ { "id": "p1", "start": 0, "end": 120 } ],
  "nodes": [
    {
      "id": "n1",
      "paragraph": "p1",
      "span": { "start": 0, "end": 40 },        // 原文中の位置
      "summary": "都市部の人口集中は続く",       // 図のラベル（10〜20字）
      "role": "claim"                            // claim | ground | fact | example | rebuttal | concession | conclusion | question
    }
  ],
  "edges": [
    {
      "from": "n1", "to": "n2",
      "type": "cause",                           // cause | reason | contrast | concession | example | restate | addition | condition | conclusion
      "evidence": "そのため",                    // 根拠となる語句（暗黙なら null）
      "explicit": true,
      "confidence": 0.9,
      "origin": "rule"                           // rule | llm | manual
    }
  ],
  "markers": [ { "type": "topic_shift", "at": "n7" } ]
}
```

- `origin` で、ルール・AI・手動のどれが付けた関係かを区別する。手動修正はデバッグ用（Q7）なので、この区別が重要。
- `span` を持たせることで、本文パネルとの相互ハイライトと SVG の原文表示ができる。
- 関係型の最終セットは 01 §3.2 の検討後に確定する。

## 6. 画面構成（案）

```
┌──────────────────────────────────────────────────┐
│ ツールバー: 入力 / 抽出方式(ルール|LLM|API) / 再生 / 書き出し │
├───────────────┬──────────────────────────────────┤
│ 本文パネル      │ 議論マップ（俯瞰）                 │
│ 段落・文ごとに  │  結論                             │
│ 色付け。       │   ▲                              │
│ クリックで図の  │  主張 ←─逆接─ 反論                │
│ ノードへ       │   ▲                              │
│               │  根拠 → 例                        │
│               │                                  │
│               │ ステップ再生: ◀ ▶ [====----] 7/12   │
├───────────────┴──────────────────────────────────┤
│ 詳細パネル: 選択中のノード/エッジ。関係型・根拠語句・手動修正   │
└──────────────────────────────────────────────────┘
```

- 俯瞰（Q4）: 議論マップが主画面。
- 追跡（Q4）: 本文パネルとの相互ハイライト、ステップ再生。
- デバッグ（Q7）: 詳細パネルで関係型を付け替え、`origin: "manual"` で保存。
