# 検討7: サンプル文章と正解データ

[03 の「次にやること」2](03_未決事項と質問.md) を実施した記録。
論説文 4 本に手で正解の構造を付け、[05 のスキーマ](05_中間表現スキーマ.md)で表現できるかを検証した。
実データは [`samples/`](../samples/) に JSON で置いてある。

## 1. 目的

このデータは 2 つの役目を持つ。

1. **スキーマの検証**: 実際の文章を 05 の型で表せるか。表せない箇所がスキーマの穴になる。
2. **評価の物差し**: 段階0（ルールのみ）と段階1（ブラウザ内 LLM）の精度を測る基準。
   [02 §4-7](02_AI利用方針.md) で「これが無いとプロンプト改善が勘頼みになる」と書いた、その正解データにあたる。

文章は著作権の問題を避けるため、すべて本プロジェクト用に書き下ろした。

## 3. 注釈方針（今回決めたこと）

正解を付ける過程で判断が必要になった点と、その決定。

### 3.1 まとまりに対する逆接は、まとまりの代表ノードに繋ぐ

「A である。B でもある。**しかし** C だ」の「しかし」は、直前の文 B ではなく A・B のまとまり全体に係ることが多い。
ノードは文単位なので、**まとまりの代表ノード**（`role` が `claim` / `rebuttal` のもの。無ければまとまりの先頭文）に繋ぐ。

- 例: S2 の `n2 → n4`（`n3` ではない）、S4 の `n1 → n3`（`n2` ではない）。
- 段階0 は直前の文に繋ぐため、ここは構造的にズレる。段階1 で改善すべき代表的な箇所。
- 将来ノードのグループ化（まとまりを 1 つの箱にする）を入れるなら、この繋ぎ先をグループにできる。

### 3.2 1 文内で完結する条件・因果はエッジにしない

S3 の「**もし**読書が情報の取得だけを目的とする**なら**、電子書籍が有利だろう」や
「文字の大きさを変えられる**ため**、読みやすい」は、1 文の中で関係が閉じている。
「1 文 = 1 ノード」の原則（05 §3）では表せないため、**エッジを作らない**。

結果として `condition` 型は 4 本のサンプスで一度もエッジにならなかった。
節分割（1 文を複数ノードに割る）を入れるまで、`condition` は実質的に使われない型になる。
型自体は残すが、**段階0 では検出も描画もしない**ことにする（05 §5 の「要検討」への回答）。

### 3.3 問いと結論の対応に新しい関係型は作らない

S2 は「学校に制服は必要だろうか」で始まり、最後の文がその答えになっている。
これを表す関係型（`answer` など）を足すことも考えたが、**作らない**。

- 理由: 関係型は 6〜8 種に抑える方針（01 §3.2）で、既に 7 種ある。
- 代わりに `role: "question"` と `role: "conclusion"` の対応で示し、図では問いを最上部に独立した枠で置く。

## 4. 段階0（ルールのみ）で取れるかの予測

各エッジについて、05 §5 の接続表現辞書だけで取れるかを見積もった。
**これは実装前の予測であり、実測値ではない。** 段階0 の実装後に同じ表を実測で埋め直す。

| サンプル | 正解エッジ | 完全一致で取れる見込み | 誤って作る見込み |
|---|---|---|---|
| S1 | 5 | 4 | 0 |
| S2 | 5 | 0 | 2 |
| S3 | 5 | 3 | 1 |
| S4 | 5 | 1 | 1 |
| 合計 | 20 | 8 | 4 |

予測値: 再現率 8/20 = 0.40、適合率 8/12 = 0.67。

取れない理由の内訳:

| 理由 | 件数 | 例 |
|---|---|---|
| 接続表現が無い（暗黙関係） | 5 | S1 `n2→n6`、S2 `n2→n3` など |
| 型は合うが係り先を誤る（3.1 のズレ） | 4 | S2 `n2→n4` を `n3→n4` と繋ぐ |
| 接続表現が辞書に無い | 2 | S4「ただし」「というのがその根拠だ」 |
| 「確かに」と「しかし」が隣接しない | 1 | S3。05 §5 の規則は次文しか見ない |

段階1（ブラウザ内 LLM）の価値は、**暗黙関係 5 件の再現率**と、**係り先のズレ 4 件の解消**で測る。

## 5. 評価指標の定義

段階0 / 段階1 / 手動修正を同じ物差しで比べるために、次のように定義する。

- **完全一致**: `from`・`to`・`type` の 3 つがすべて一致したエッジ。
- **型のみ一致**: `type` は合うが端点が違うもの。別枠で数える（3.1 のズレがここに出る）。
- **再現率** = 完全一致数 ÷ 正解エッジ数、**適合率** = 完全一致数 ÷ 出力エッジ数、F1 はその調和平均。
- 集計は `explicit` の真偽で分けて出す。段階1 の価値は暗黙側にしか現れないため。
- `role` の正解率は別に測る（段階0 は `role` を付けないので段階1 以降の指標）。

評価スクリプトは段階0 の実装と同時に作る（[06 §3](06_開発体制と分担方針.md) の分担では crab2424 側）。

## 6. スキーマへの反映（05 を更新済み）

このデータを作る過程で見つかった穴を 05 に反映した。

| 見つかった穴 | 対応 |
|---|---|
| 人手の正解データを `meta.extractor`（`rule` / `webllm` / `api`）で表せない | `"manual"` を追加 |
| サンプルを識別する名前を持てない | `meta.title`（任意）を追加 |
| 「ただし」「とはいえ」「一方で」が逆接辞書に無い | 辞書に追加 |
| 「というのがその根拠だ」など、理由を示す文末表現の取りこぼし | 辞書に追加 |
| 「確かに」の待機が次文しか見ない | 同じ段落内の後続文まで見るよう規則を修正 |
| `condition` の扱いが未決だった | 3.2 のとおり決定（段階0 では扱わない） |
