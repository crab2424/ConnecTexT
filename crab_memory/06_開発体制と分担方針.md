### 3.1 並行作業できる理由

**中間表現 JSON（[05](05_中間表現スキーマ.md)）が両者のインターフェースになる。**
抽出側（[1]〜[3]）と描画側（[4]〜[6]）は、この型を介してしか繋がらない。

さらに [`samples/`](../samples/) に正解データを 4 本置いたので、
**描画側は抽出器の完成を待たずに開発できる**。サンプル JSON をそのまま読み込めば、
ノード・エッジが揃った状態で議論マップやパネルを作れる。

逆に抽出側は、描画を待たずに評価スクリプト（07 §5 の指標）で精度を確認できる。

## 4. 進め方

1. PR① `merge/design-latest-into-main` → `main` をマージする。
2. PR② `chore/dev-rules-v2` → `main` をマージする。
3. **`main` のブランチ保護を有効化する**（リポジトリオーナー = crab2424 の作業。GitHub の
   Settings → Branches。手順は `CONTRIBUTING.md` §6）。直接 push が既に 1 件発生しているため優先。
4. 旧ブランチ（`merge/demo-design-into-main`、`chore/dev-rules`、`デモ設計`）を削除する。
5. 雛形の作成（frogama55）と、段階0 の実装（crab2424）に入る。
6. 実装タスクは §3 の表の単位で Issue に切る。
