## 2. 見つかった問題

`merge/demo-design-into-main` は `c2353bc`（Q1〜Q10 まで回答した時点）を起点にしており、
その後の `9714c56`（Q11〜Q15 の回答、`05_中間表現スキーマ.md` の追加）を取り込んでいない。

（`main` の README 修正を merge しただけ）。

つまり `chore/dev-rules` はこの古い状態の上に構築されており、**このまま `main` に merge すると**:

- Q11〜Q15（費用方針・技術スタック・ホスティング・保存形式）の決定が「未回答」の状態に戻る
- `05_中間表現スキーマ.md`（関係型7種の確定、TypeScript 型定義、接続表現辞書、注釈済みサンプル）が消える

問題は**ベースが古い**ことだけ。

## 4. 進め方（提案）

1. **統合順序**: 先に `デモ設計`（このブランチ）の設計ドキュメント（Q1〜Q15、05含む）を `main` に取り込む。
   その後 `chore/dev-rules` を更新後の `main` に対して作り直す（rebase または再作成）。
2. **Q11〜Q15 の確認**: crab2424 が一人で回答したため、frogama55 に内容の確認を依頼する
   （特に Q13 技術スタックと Q14 ホスティングは共同作業に直結する）。
3. **ブランチ保護**: `chore/dev-rules` の `CONTRIBUTING.md` が提案している `main` の保護設定
   （PR必須・force push禁止・削除禁止）を、上記の統合が終わり次第すぐに有効化する。
   直接 push が既に1件発生しているため優先度を上げる。
4. **今後のやり取り**: 設計・運用ともに GitHub の Issue / PR 上で行い、ブランチの状態は
   `crab_memory/README.md` と本ファイルで随時更新する。
