# 中間表現スキーマ（たたき台 v1）

01 §3 と 04 §5 を受けて、関係型の最終セットと中間表現の型を決める。
ここが決まると、ルール層・AI 層・描画・手動修正・書き出しの全部がこの型を介して独立に作れる。

## 1. 関係型（エッジの `type`）: 7 種

01 §3.2 の 10 候補から、次の方針で 7 種に絞った。

- 「理由（なぜなら）」「帰結（したがって）」は、接続表現が違うだけで関係は「因果」と同じ。
  矢印の向きを「原因・根拠 → 結果・主張」に統一すれば 1 種にまとめられる。
- 「転換（ところで）」はノード同士の関係ではなく区切りなので、エッジではなく `markers` に置く。
- 「結論」はエッジ型ではなくノードの `role` で表す。

| `type` | 名前 | 向き（from → to） | 典型的な接続表現 | 線の案 | 動き（01 §5.1） |
|---|---|---|---|---|---|
| `cause` | 因果 | 原因・根拠 → 結果・主張 | だから、したがって、そのため、その結果、なぜなら、〜からだ | 実線の矢印 | 流れる・支える |
| `contrast` | 逆接・対比 | 先行 → 後続 | しかし、だが、ところが、一方 | 赤い折れ矢印 | 押し返す |
| `concession` | 譲歩 | 譲る側 → 本命の主張 | 確かに〜が、もちろん〜しかし | 赤い点線の折れ矢印 | 受け止めてから押し返す |
| `example` | 例示 | 例 → 一般命題 | 例えば、具体的には、〜など | 細い点線 | 脇に並ぶ |
| `restate` | 言い換え・要約 | 元 → 言い換え | つまり、要するに、すなわち | 二重線（矢印なし） | 重なって置き換わる |
| `addition` | 添加・並列 | 先行 → 後続 | また、さらに、そして、加えて | 灰色の細線（矢印なし） | 隣に積み上がる |
| `condition` | 条件・仮定 | 条件 → 帰結 | もし〜なら、〜すれば、〜の場合 | 破線の矢印 | 分岐する |

向きの原則: **矢印は「支える・導く」方向**。読み順とは独立させる（「なぜなら」は後ろの文が前の文を支えるので、矢印は後ろ → 前）。
読み順はノードの `span` から分かるので、エッジに持たせる必要はない。

## 2. ノードの `role`: 7 種（論説文向け、任意）

| `role` | 意味 | 図での扱い |
|---|---|---|
| `claim` | 主張 | 太枠 |
| `conclusion` | 結論（文章全体の主張） | 太枠、最上段 |
| `ground` | 根拠・理由 | 通常 |
| `fact` | 事実・データ | 通常、薄い背景 |
| `example` | 例 | 小さめ |
| `rebuttal` | 反論・対立意見 | 赤枠 |
| `concession` | 譲歩（相手の言い分を認める部分） | 赤の点線枠 |
| `question` | 問い・問題提起 | 角丸 |

役割はルール層では付けにくい（接続詞だけでは決まらない）ので、段階0 では `null` を許し、段階1 以降と手動修正で埋める。

## 3. 型定義（TypeScript。zod スキーマはこれから起こす）

```ts
type RelationType =
  | "cause" | "contrast" | "concession" | "example"
  | "restate" | "addition" | "condition";

type Role =
  | "claim" | "conclusion" | "ground" | "fact"
  | "example" | "rebuttal" | "concession" | "question";

type Origin = "rule" | "llm" | "manual";

interface Span { start: number; end: number }   // 原文中の文字位置（UTF-16 のインデックス、end は排他的）

interface Paragraph { id: string; span: Span }

interface Node {
  id: string;
  paragraph: string;          // Paragraph.id
  span: Span;                 // 原文の範囲。本文パネルとの相互ハイライトに使う
  summary: string;            // 図のラベル。10〜20 字。段階0 では原文の先頭を切り出す
  role: Role | null;
  origin: Origin;             // summary / role を付けた主体
}

interface Edge {
  id: string;
  from: string;               // Node.id（支える側）
  to: string;                 // Node.id（導かれる側）
  type: RelationType;
  evidence: string | null;    // 根拠となる語句。暗黙なら null
  explicit: boolean;          // 接続表現が明示されているか
  confidence: number;         // 0〜1。ルールは 1.0、手動は 1.0
  origin: Origin;
}

interface Marker {
  id: string;
  type: "topic_shift";        // 将来: "question", "summary_start" など
  at: string;                 // Node.id（この直前で区切る）
  evidence: string | null;
}

interface Document {
  version: 1;
  source: { text: string; lang: "ja" };
  paragraphs: Paragraph[];
  nodes: Node[];
  edges: Edge[];
  markers: Marker[];
  meta: {
    title?: string;           // サンプル名・文章のタイトル（任意）
    extractor: "rule" | "webllm" | "api" | "manual";  // manual = 人手で作った正解データ
    createdAt: string;        // ISO 8601
    edited: boolean;          // 手動修正が入っているか
  };
}
```

設計上の決め事:
- ノードは基本「1 文 = 1 ノード」。1 文に複数の命題がある場合の分割は段階1 以降の課題にする。
- 手動修正はエッジの追加・削除・`type` 変更と、ノードの `summary` / `role` 変更。修正したものは `origin: "manual"` に書き換える。
- 書き出しはこの `Document` をそのまま JSON にする。読み込み時に zod で検証する。
- **まとまりに対する逆接**は、直前の文ではなく、まとまりの代表ノード（`role` が `claim` / `rebuttal` のもの。
  無ければまとまりの先頭文）に繋ぐ。段階0 は直前の文に繋ぐため、ここは構造的にズレる（→ [07 §3.1](07_サンプルと正解データ.md)）。
- **1 文内で閉じた関係**（「〜なら〜だろう」「〜ため〜」）はエッジにしない。節分割を入れるまでの割り切り（→ [07 §3.2](07_サンプルと正解データ.md)）。
- **問いと結論の対応**に関係型は作らない。`role: "question"` と `role: "conclusion"` で表す（→ [07 §3.3](07_サンプルと正解データ.md)）。

## 4. 注釈済みサンプル

段階0 の動作確認と、正解データの形式の見本。

### 原文（6 文）

```
近年、都市部への人口集中が進んでいる。その結果、地方では働き手が不足し、産業の維持が難しくなっている。確かに、都市には雇用や教育の機会が多い。しかし、集中が続けば災害時の被害は拡大し、生活費も上がり続ける。例えば、東京では家賃が十年で二割以上上がった。したがって、地方への移住を促す政策が必要である。
```

### ノード

| id | 原文 | summary | role |
|---|---|---|---|
| n1 | 近年、都市部への人口集中が進んでいる。 | 都市部への人口集中が進む | fact |
| n2 | その結果、地方では働き手が不足し、産業の維持が難しくなっている。 | 地方の働き手不足と産業維持の困難 | ground |
| n3 | 確かに、都市には雇用や教育の機会が多い。 | 都市には機会が多い | concession |
| n4 | しかし、集中が続けば災害時の被害は拡大し、生活費も上がり続ける。 | 集中が続くと被害拡大・生活費上昇 | ground |
| n5 | 例えば、東京では家賃が十年で二割以上上がった。 | 東京の家賃が十年で二割上昇 | example |
| n6 | したがって、地方への移住を促す政策が必要である。 | 地方移住を促す政策が必要 | conclusion |

### エッジ

| from | to | type | evidence | explicit | 段階0 で取れるか |
|---|---|---|---|---|---|
| n1 | n2 | cause | その結果 | true | 取れる |
| n3 | n4 | concession | 確かに／しかし | true | 取れる（「確かに」＋次文の「しかし」の組で判定） |
| n5 | n4 | example | 例えば | true | 取れる |
| n4 | n6 | cause | したがって | true | 取れる（直前の文に繋ぐ） |
| n2 | n6 | cause | null | false | **取れない**（段階1 か手動で補う） |

段階0 の限界がこの例に出ている。「したがって」は直前の n4 だけに繋ぎ、n2 からの繋がりは接続詞が無いので拾えない。
段階1（ブラウザ内 LLM）の価値はこの `n2 → n6` のような暗黙関係を補えるかで測る（04 §7）。

### 図のイメージ（議論マップ、俯瞰）

```
                 ┌──────────────────────┐
                 │ n6 地方移住を促す政策が必要 │  conclusion
                 └──────────────────────┘
                     ▲               ▲
        cause(暗黙)  │               │ cause「したがって」
                     │               │
   ┌────────────────────┐   ┌────────────────────────┐
   │ n2 地方の働き手不足 …  │   │ n4 集中が続くと被害拡大 …  │ ◀── concession「確かに／しかし」── [n3 都市には機会が多い]
   └────────────────────┘   └────────────────────────┘
             ▲                          ▲
  cause      │                          │ example「例えば」
「その結果」  │                          │
   ┌────────────────────┐   ┌────────────────────────┐
   │ n1 都市部への人口集中  │   │ n5 東京の家賃が十年で二割上昇 │
   └────────────────────┘   └────────────────────────┘
```

## 5. 接続表現辞書（段階0 のルール層。初版）

文頭または文中の接続表現を照合し、エッジを生成する。`prev` は直前の文、`cur` は当該文。

| 接続表現 | type | from → to | 備考 |
|---|---|---|---|
| だから、したがって、よって、ゆえに、そのため、その結果、このように、以上より | cause | prev → cur | 「このように」「以上より」は cur の role を conclusion 候補にする |
| なぜなら、というのも、〜からだ。、〜ためである。、というのがその根拠だ、その理由は〜 | cause | cur → prev | 文末表現も見る |
| しかし、だが、ところが、けれども、一方、一方で、逆に、それに対して、ただし、とはいえ | contrast | prev → cur | 同じ段落内の先行文に「確かに」があれば concession に格上げ |
| 確かに、もちろん、無論 | （待機） | ― | **同じ段落内の**後続文に contrast があれば concession（cur → その文）を生成。単独ではエッジを作らない |
| 例えば、たとえば、具体的には、〜など | example | cur → prev | 例は直前の一般命題を支える |
| つまり、要するに、すなわち、言い換えれば | restate | prev → cur | |
| また、さらに、そして、加えて、それに、および | addition | prev → cur | 「そして」は順接の場合もあるが、段階0 では addition に倒す |
| もし、仮に、〜ならば、〜すれば、〜の場合 | condition | （段階0 では扱わない） | 1 文内で閉じるため、文単位のノードでは表せない。節分割を入れるまで検出も描画もしない（07 §3.2） |
| ところで、さて、次に、では | marker: topic_shift | at = cur | |

制約と割り切り:
- 接続表現が無い文は、段階0 ではエッジを作らない（`addition` で機械的に繋ぐ案もあるが、図がノイズになるので作らない）。
- 段落をまたぐ関係は、段落の先頭文に接続表現があれば prev を「前段落の末尾文」として扱う。
- `condition` は 1 文内で完結することが多く、文単位のノードでは表しにくい。**段階0 では扱わない**と決めた（07 §3.2）。
  型の定義自体は残すが、節分割（1 文を複数ノードに割る）を入れるまで実際には使われない。
